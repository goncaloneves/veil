# AGENTS.md

veil masks secrets before a coding agent's model sees them. Read [CONTRIBUTING.md](CONTRIBUTING.md) and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) before changing code.

- Never put a real or real-looking secret in the repository, a test, an issue or a commit. Tests build fake tokens at run time with `test/helpers.ts` and the seeded `fakeHex` in `tests/claude-code/veil.test.ts`.
- veil has no runtime dependencies. Do not add one.
- `src/core`, `src/sources`, `src/config`, `src/rules`, `src/engine.ts` and `src/report.ts` use no Node, browser or agent API; `npm run typecheck` enforces it.
- Every integration goes through `Veil` in `src/session.ts` and the restore rule in `src/restore.ts`; never write a second masking or restore path. Wire-format knowledge lives in `src/wire`.
- In the Claude Code adapter, every `$` call is written inline in `hooks/register.ts`; helpers never take `$`.
- `src/rules/gitleaks.ts` is generated by `node scripts/sync-gitleaks.ts`; never edit it by hand.
- Write no code comments.
- Use conventional commits (`feat:`, `fix:`, `docs:` …); release-please builds versions and the changelog from them.
- Before calling a change done: `npm run typecheck`, `npm test`, `claude plugin validate .` and `claude plugin test .` all pass.
